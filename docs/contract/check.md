# Check contract

Generated from the `CheckEnvelope` types in `mnemic-core`. Do not edit this file by hand. Run `cargo run -p mnemic-core --bin mnemic-contract`.

## Envelope

`mnemic check --json` prints one JSON document.

A clean tree is `ok: true`, `data.errors` and `data.warnings` empty, `error: null`, exit 0.

Findings (`BAD_ID`, `MISSING_FIELD`, `BAD_FRONTMATTER`, `UNKNOWN_TYPE`, `ALIAS_CONTACT`, `SCHEMA_VERSION_AHEAD`, `INVALID_PACK`, `DUPLICATE_ID`, `ALIAS_NOT_UNIQUE`, `SUPERSEDED_WITHOUT_INCOMING`, `SUPERSEDES_CYCLE`, `BROKEN_LINK`, `SHA256_DRIFT`, `AMBIGUOUS`) use `ok: false`, `data` with those findings, and `error.code` `CHECK_FAILED`. Exit 2.

Fatal codes use `ok: false`, `data: null`, and `error.code` set to the fatal code. `VAULT_NOT_FOUND`, `USAGE`, `BAD_CONFIG`, `UNSUPPORTED_VAULT_VERSION`, and `NESTED_VAULT` are fatal. They are never entries in `data.errors`. `init` returns `NESTED_VAULT` when a parent of the target already has `mnemic.toml`.

## Finding codes

| Code | Meaning |
| --- | --- |
| `BAD_ID` | `id` is present and is not a 26-character ULID |
| `MISSING_FIELD` | A required core field is absent, a source note has neither `path` nor `url`, or a required type field such as journal `date` is absent |
| `BAD_FRONTMATTER` | No frontmatter, a non-mapping, a duplicate YAML key, an unterminated `---` fence, or a present core field with an invalid value |
| `UNKNOWN_TYPE` | `type` is not in the loaded pack |
| `ALIAS_CONTACT` | An `aliases` entry is an email address or a phone number |
| `SCHEMA_VERSION_AHEAD` | The note `schema_version` is newer than the loaded type |
| `INVALID_PACK` | A type pack file is missing a required key, is not valid TOML, or is a symlink or path outside the vault |
| `DUPLICATE_ID` | Two notes use one `id` |
| `ALIAS_NOT_UNIQUE` | One alias, after NFC case-folding, maps to two ids |
| `SUPERSEDED_WITHOUT_INCOMING` | `status` is `superseded` and no other note points at it with `supersedes` |
| `SUPERSEDES_CYCLE` | `supersedes` links form a cycle |
| `BROKEN_LINK` | A wikilink, embed, typed link, or `supersedes` target does not resolve |
| `SHA256_DRIFT` | A source note `sha256` does not match the raw file at `path`, or `path` is not a regular file inside the vault |
| `AMBIGUOUS` | A link matches more than one note. `error.details.candidates` lists `path`, `link`, and `matches` |

The JSON Schema for the envelope is [`check.schema.json`](check.schema.json).

## `mnemic log`

`mnemic log <note> <text> --json` prints one JSON document. `<note>` is a path, id, slug, or alias, resolved inside the write lock.

Success is `ok: true`, `error: null`, exit 0, and `data` with `id`, `path`, `noop`, `line`, and `heading_created`. `line` is the timeline item, including the `- ` marker. `noop` is true when that exact line is already on the page. `heading_created` is true when this call added `## Timeline`.

`NOT_FOUND`, `AMBIGUOUS`, `USAGE`, `TIMELINE_DISABLED`, `TIMELINE_HEADING_AMBIGUOUS`, and `OUTSIDE_VAULT` are fatal for `log`. Exit 2. `LOCK_HELD` is exit 75. `IO` is exit 1. `OUTSIDE_VAULT` means the resolved path canonicalizes outside the vault, including an outside symlink. The check finding `AMBIGUOUS` is a different code from the fatal `AMBIGUOUS` on `log`.

## Search

`mnemic search <query> [--type <type>] [--tag <tag>] [--since <date>] [--limit <n>] [--json]` scans the parsed note-file set. There is no index command and no query language. Tokens are whitespace-separated. Matching is case-insensitive Unicode lowercase with no diacritic folding. Every token must occur in the title, an alias, or the body. `-`, `"`, and `:` are literal characters.

`--type` is an exact type name. `--tag` matches a `tags` entry that equals the value or starts with `<value>/`. `--since` keeps notes whose `updated` is that ISO date or datetime, inclusive. A date is midnight UTC. The default `--limit` is 20. `--limit` of zero or less and an empty query are `USAGE`, exit 2. Zero hits is `ok: true`, `hits: []`, exit 0.

Ranking puts a title match ahead of a body or alias match, then a higher token count, then a later `updated`, then `id` ascending. `score` is that order starting at 1. `section` is `truth` or `timeline`. Timeline is the body from a line `## Timeline` onward. `snippet` is the first matching title, alias, or line, cut at 200 characters.

An entry that is not a regular file inside the vault is not a note, so it is not a hit and search does not error. `search` also returns `VAULT_NOT_FOUND` and `IO`. It does not return an FTS syntax error.

## Envelope

`mnemic check --json` prints one JSON document.

A clean tree is `ok: true`, `data.errors` and `data.warnings` empty, `error: null`, exit 0.

Findings (`BAD_ID`, `MISSING_FIELD`, `BAD_FRONTMATTER`, `UNKNOWN_TYPE`, `ALIAS_CONTACT`, `SCHEMA_VERSION_AHEAD`, `INVALID_PACK`, `DUPLICATE_ID`, `ALIAS_NOT_UNIQUE`, `SUPERSEDED_WITHOUT_INCOMING`, `SUPERSEDES_CYCLE`, `BROKEN_LINK`, `SHA256_DRIFT`, `AMBIGUOUS`) use `ok: false`, `data` with those findings, and `error.code` `CHECK_FAILED`. Exit 2.

Fatal codes use `ok: false`, `data: null`, and `error.code` set to the fatal code. `VAULT_NOT_FOUND`, `USAGE`, `BAD_CONFIG`, `UNSUPPORTED_VAULT_VERSION`, and `NESTED_VAULT` are fatal. They are never entries in `data.errors`. `init` returns `NESTED_VAULT` when a parent of the target already has `mnemic.toml`. `get` and `links` return `NOT_FOUND` when the resolver misses, `AMBIGUOUS` when a slug or alias matches more than one note (`error.details.candidates` lists `id` and `path`), and `OUTSIDE_VAULT` when a path escapes the vault. Those three are fatal. A missing id and a missing slug both use `NOT_FOUND`. `mv` adds `DEST_EXISTS`, `NOTE_ARCHIVED`, `ALIAS_NOT_UNIQUE`, `SLUG_COLLISION`, and `RAW_IMMUTABLE`. A path that leaves the vault is `OUTSIDE_VAULT`.

## `check --fix`

`mnemic check --fix [--json] [--vault <path>] [path]` uses the same discovery as `check`. It inserts a missing `id` (Crockford ULID; the time component comes from the clock, not mtime) and a missing `type` when the note's top-level folder equals exactly one type's `folder` (`folder` is a string or a list; `inbox/` and `notes/` both derive `note`). A file with no frontmatter block gets a new `---` block that holds only those derived keys. A malformed `id`, a folder that maps to no type or to more than one, and every other field stay untouched. `title`, `created`, `updated`, `created_by`, `status`, and the body are not invented. `updated` is not stamped. Root `AGENTS.md` and `README.md` are not notes, so they are not fixed. Bytes outside the inserted lines stay identical.

One write lock covers the vault. Resolve and read happen under that lock. Writes go through `FrontmatterEdit` and `WriteTxn::atomic_write`. A second run on a still-valid result writes nothing. An I/O error after some files were renamed leaves those files fixed. A later run finishes the rest.

`--json` always includes `data.changes` on `--fix`: `{ "path", "field": "id"|"type", "old": null, "new" }`. When findings remain, the shape is `CHECK_FAILED`, exit 2, and `data.changes` still lists what was written. `USAGE`, `VAULT_NOT_FOUND`, `LOCK_HELD`, `IO`, and `OUTSIDE_VAULT` use `data: null`. A path that canonicalizes outside the vault is `OUTSIDE_VAULT` and is not written.

Unexpected I/O uses `IO` and exit 1. Every other fatal code and `CHECK_FAILED` use exit 2.

## Finding codes

| Code | Meaning |
| --- | --- |
| `BAD_ID` | `id` is present and is not a 26-character ULID |
| `MISSING_FIELD` | A required core field is absent, a source note has neither `path` nor `url`, or a required type field such as journal `date` is absent |
| `BAD_FRONTMATTER` | No frontmatter, a non-mapping, a duplicate YAML key, an unterminated `---` fence, or a present core field with an invalid value |
| `UNKNOWN_TYPE` | `type` is not in the loaded pack |
| `ALIAS_CONTACT` | An `aliases` entry is an email address or a phone number |
| `SCHEMA_VERSION_AHEAD` | The note `schema_version` is newer than the loaded type |
| `INVALID_PACK` | A type pack file is missing a required key, is not valid TOML, or is a symlink or path outside the vault |
| `DUPLICATE_ID` | Two notes use one `id` |
| `ALIAS_NOT_UNIQUE` | One alias, after NFC case-folding, maps to two ids |
| `SUPERSEDED_WITHOUT_INCOMING` | `status` is `superseded` and no other note points at it with `supersedes` |
| `SUPERSEDES_CYCLE` | `supersedes` links form a cycle |
| `BROKEN_LINK` | A wikilink, embed, typed link, or `supersedes` target does not resolve |
| `SHA256_DRIFT` | A source note `sha256` does not match the raw file at `path`, or `path` is not a regular file inside the vault |
| `AMBIGUOUS` | A link matches more than one note. `error.details.candidates` lists `path`, `link`, and `matches` |

## Search

`mnemic search <query> [--type <type>] [--tag <tag>] [--since <date>] [--limit <n>] [--json]` scans the parsed note-file set. There is no index command and no query language. Tokens are whitespace-separated. Matching is case-insensitive Unicode lowercase with no diacritic folding. Every token must occur in the title, an alias, or the body. `-`, `"`, and `:` are literal characters.

`--type` is an exact type name. `--tag` matches a `tags` entry that equals the value or starts with `<value>/`. `--since` keeps notes whose `updated` is that ISO date or datetime, inclusive. A date is midnight UTC. The default `--limit` is 20. `--limit` of zero or less and an empty query are `USAGE`, exit 2. Zero hits is `ok: true`, `hits: []`, exit 0.

Ranking puts a title match ahead of a body or alias match, then a higher token count, then a later `updated`, then `id` ascending. `score` is that order starting at 1. `section` is `truth` or `timeline`. Timeline is the body from a line `## Timeline` onward. `snippet` is the first matching title, alias, or line, cut at 200 characters.

An entry that is not a regular file inside the vault is not a note, so it is not a hit and search does not error. `search` also returns `VAULT_NOT_FOUND` and `IO`. It does not return an FTS syntax error.

`--json` success:

`ok`, `data.query`, `data.hits[]` with `id`, `path`, `title`, `type`, `snippet`, `section`, `score`, and `error: null`.

## `mnemic new`

Success is `ok: true`, `error: null`, exit 0, and `data` with `id`, `path`, and `noop`. `path` is vault-relative. `noop` is true only when that `id` is already the note at that path. The file is not rewritten.

## `mnemic mv`

`mnemic mv <note> <dest> [--no-rewrite] [--vault <dir>] --json` prints one JSON document. `<note>` is a path, id, slug, or alias. `<dest>` is a vault-relative file or directory.

Success is `ok: true`, `error: null`, exit 0, and `data` with `id`, `from`, `to`, `alias_added`, and `rewritten`. `from` and `to` are vault-relative paths. `alias_added` is true when this call appended the old slug to `aliases`. `rewritten` lists notes whose incoming wikilinks were updated. `--no-rewrite` leaves those wikilinks unchanged, so `rewritten` is empty.

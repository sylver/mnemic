# Check contract

Generated from the `CheckEnvelope` types in `mnemic-core`. Do not edit this file by hand. Run `cargo run -p mnemic-core --bin mnemic-contract`.

## Envelope

`mnemic check --json` prints one JSON document.

A clean tree is `ok: true`, `data.errors` and `data.warnings` empty, `error: null`, exit 0.

Findings (`BAD_ID`, `MISSING_FIELD`, `BAD_FRONTMATTER`, and later check codes) use `ok: false`, `data` with those findings, and `error.code` `CHECK_FAILED`. Exit 2.

Fatal codes use `ok: false`, `data: null`, and `error.code` set to the fatal code. `VAULT_NOT_FOUND`, `USAGE`, `BAD_CONFIG`, and `UNSUPPORTED_VAULT_VERSION` are fatal. They are never entries in `data.errors`.

## Exit codes

| Code | Exit |
| --- | --- |
| `USAGE` | 2 |
| `VAULT_NOT_FOUND` | 2 |
| `BAD_CONFIG` | 2 |
| `UNSUPPORTED_VAULT_VERSION` | 2 |
| `IO` | 1 |
| `LOCK_HELD` | 75 |
| `CHECK_FAILED` | 2 |

`LOCK_HELD` is reserved at exit 75. `check` does not take the vault lock.

Unexpected I/O uses `IO` and exit 1. Every other fatal code and `CHECK_FAILED` use exit 2.

## Finding codes

| Code | Meaning |
| --- | --- |
| `BAD_ID` | `id` is present and is not a 26-character ULID |
| `MISSING_FIELD` | A required core field is absent |
| `BAD_FRONTMATTER` | No frontmatter, a non-mapping, a duplicate YAML key, an unterminated `---` fence, or a present core field with an invalid value |
